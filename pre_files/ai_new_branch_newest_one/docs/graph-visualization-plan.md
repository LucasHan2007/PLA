# 知识图谱可视化改进规划

## 一、两种布局风格详解与推荐

### A. 技能树 / 路径型（Skill Tree / Path Layout）

**像什么**：RPG 游戏的天赋树、LabEx 学习路径、课程大纲

**核心特点**：
- 有一个明确的"根节点"（项目目标）在顶部或左侧
- 向下/向右层层展开：目标 → 阶段 → 任务 → 知识点
- 节点之间有严格的**先后依赖关系**，用带箭头的连线表示
- 同层节点并列，表示同一阶段的不同方面

**优点**：
- ✅ **目标感强**：一眼看到"完成这个项目需要几步"，当前在第几步
- ✅ **路径清晰**：知道"学完了 A 才能解锁 B"，不会迷失方向
- ✅ **适合项目驱动学习**：你的 LearnScaffold 本身就是阶段式推进的（理解→方案→拆解→实现→调试）
- ✅ **与 Markdown 联动天然**：Project 区的项目规划大纲本身就是树形结构，可以直接映射

**缺点**：
- ❌ 不适合展示"知识点之间多对多的复杂关联"（比如"多线程"既属于"性能优化"又属于"并发编程"）
- ❌ 如果知识点太多，树会变得很宽/很深

**适用场景**：
- 项目学习路径、课程大纲、技能进阶路线
- **你的场景**：LKG 作为围绕项目的能力掌握图，每个知识点都有明确的项目阶段归属

---

### B. 力导向网络图（Force-Directed Network Graph）

**像什么**：Obsidian Graph View、思维导图、社交网络图

**核心特点**：
- 节点像磁铁一样自动排列，有关联的节点靠得近
- 没有固定的"上下左右"层级，全靠连接密度决定位置
- 节点大小可以表示"中心性"（被引用/依赖越多，节点越大）
- 支持多对多关系（一个知识点连接多个父节点）

**优点**：
- ✅ **发现隐藏关联**：可能发现"内存模拟"和"std::filesystem"虽然属于不同阶段，但有间接关联
- ✅ **适合复杂知识网络**：当知识点之间的关联比层级更重要时
- ✅ **视觉震撼**：动态力导向动画看起来很酷

**缺点**：
- ❌ **没有明确路径**：看不出"应该先学哪个"，容易迷失
- ❌ **与项目阶段脱节**：无法直观对应"当前对话在第几步"
- ❌ **布局不稳定**：每次刷新节点位置可能不同

**适用场景**：
- 知识库全局概览、概念关联探索、文献引用网络

---

### 我的推荐：**技能树为主 + 网络图为辅的混合方案**

理由：

1. **你的项目是项目驱动学习**：LearnScaffold 的核心就是"先解析项目 → 诊断 → 闭环推进"，每个知识点都有明确的项目阶段归属，天然适合树形结构
2. **需要与 Project Markdown 联动**：项目规划大纲本身就是树形（目标→阶段→任务），图谱和 Markdown 可以互相高亮映射
3. **用户体验优先**：学习者最需要的是"我现在在哪、下一步去哪"，技能树直接回答这个问题
4. **网络图作为辅助视图**：当用户想探索"这个概念还和哪些知识点有关"时，可以切换到网络图视图，做"发散式探索"

## 二、技术选型

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **D3.js** | 功能最全、可定制性最高 | 学习曲线陡峭、代码量大、需要自己写布局算法 | ❌ 过重 |
| **Cytoscape.js** | 专为图可视化设计、内置多种布局、API 简洁、节点可拖拽、事件丰富、CDN 引入 | 不如 D3 灵活，但足够用 | ✅ **首选** |
| **ECharts Graph** | 功能全、文档好、内置力导向 | 节点拖拽支持不如 Cytoscape 自然 | 备选 |

**最终选择：Cytoscape.js**（CDN 引入，零构建成本）

理由：
- 内置 `breadthfirst` 布局（完美的技能树布局）
- 内置 `cose` 布局（力导向网络图）
- 节点拖拽一行代码启用
- 点击/悬停事件直接绑定
- 样式系统类似 CSS，美观可控

## 三、数据结构调整

当前 `project_graph.json` 的 LKG 是扁平数组，需要增加关系：

```json
{
  "project_profile": { ... },
  "pcg": { "nodes": [...], "edges": [...] },
  "lkg": {
    "nodes": [
      {
        "id": "cpp-basics",
        "name": "C++编程基础",
        "description": "掌握C++语言的基本语法和特性",
        "type": "concept",
        "status": "mastered",
        "project_phase": "需求分析",
        "x": null,
        "y": null
      }
    ],
    "edges": [
      {
        "source": "cpp-basics",
        "target": "file-io",
        "type": "prerequisite",
        "description": "需要掌握基础语法才能理解文件I/O"
      }
    ]
  },
  "latest": { ... }
}
```

后端需要：
1. 在 `update_scaffold_state` 中解析 `knowledge_edges` 并保存到 `lkg.edges`
2. 在 `parse_ai_reply` 中扩展解析 `knowledge_edges`
3. 提供 `/api/graph/update` 接口供前端修改节点状态/位置

## 四、视觉设计方案

### 配色（低饱和暖色调）

```
节点类型色：
- goal（目标）      : #f59e0b 琥珀色
- task（任务）      : #3b82f6 蓝色
- concept（概念）   : #10b981 绿色
- skill（技能）     : #8b5cf6 紫色
- tool（工具）      : #64748b 灰色

状态色：
- mastered（已掌握） : #22c55e 绿色 + 实心
- learning（在学）   : #f59e0b 琥珀色 + 脉冲动画
- locked（未解锁）  : #cbd5e1 灰色 + 虚线边框
- unknown（未知）   : #94a3b8 浅灰

连线：
- prerequisite（前置）: #94a3b8 灰色实线
- related（相关）    : #cbd5e1 浅色虚线
- used_in（用于）    : #60a5fa 蓝色
```

### 节点样式

- 形状：圆形（概念）/ 圆角矩形（任务）/ 菱形（目标）
- 大小：根据出度（子节点数）动态调整
- 标签：节点下方显示名称，hover 显示描述
- 图标：每个类型配一个 Unicode 图标（🎯📋💡🔧）

### 布局

- **主视图**：`breadthfirst` 从上到下，根节点在顶部
- **辅助视图**：`cose` 力导向，自由排列
- 画布背景：`#f8fafd` 浅灰蓝
- 画布内边距：50px

## 五、与 Project Markdown 的联动设计

**核心机制**：Project 区的 Markdown 大纲 = 图谱的树形骨架

### 联动方式 1：双向高亮

- 点击图谱中的某个节点 → Project 区 Markdown 自动滚动到对应章节并高亮
- 点击 Markdown 中的某个章节标题 → 图谱中对应节点高亮并居中

### 联动方式 2：阶段进度指示器

- 在图谱顶部添加一条"进度条"：
  ```
  项目规划 ▶ 需求分析 ▶ 场景选择 ▶ 核心功能 ▶ 内存模拟 ▶ 文件I/O ▶ 命令解析
  ```
- 当前对话所在阶段高亮显示
- 点击进度条可跳转到该阶段

### 联动方式 3：对话上下文标记

- 每次对话后，AI 在回复中标记 `current_phase`（当前阶段）
- 前端根据 `current_phase` 在图谱中高亮对应阶段的所有节点
- 在节点旁显示"当前对话涉及"徽章

## 六、半编辑交互设计

### 用户可以做的：

1. **拖拽节点**：调整布局，位置会保存到 `lkg.nodes[i].x/y`
2. **双击编辑**：修改节点名称和描述
3. **右键菜单**：
   - 标记状态：已掌握 / 在学 / 未解锁
   - 添加子节点
   - 添加关联节点（创建 cross-edge）
   - 删除节点
4. **添加备注**：在节点上挂一个便签图标，hover 显示备注内容
5. **搜索过滤**：顶部搜索框，输入关键词高亮匹配节点

### AI 负责的部分：

1. 自动从对话中抽取知识点并创建节点
2. 自动推断前置依赖关系并创建 edge
3. 自动分配节点到对应项目阶段
4. 初始布局自动计算

## 七、分阶段实施计划

**目标**：让图谱从纯文本列表变成可看的图形

**任务**：
- [ ] 引入 Cytoscape.js CDN
- [ ] 创建 `graph-renderer.js` 模块
- [ ] 解析 `project_graph.json` 中的 `pcg` 和 `lkg` 数据为 Cytoscape 元素

- [ ] 支持缩放和拖拽画布

**验收标准**：打开 Project 面板能看到一棵有颜色、可缩放、节点可拖拽的树

---

### 阶段 2：与 Project Markdown 联动（1 天）

---

### 阶段 3：半编辑交互（1-2 天）

## 九、风险与回退方案

| 风险 | 应对 |
|------|------|
| Cytoscape.js CDN 加载失败 | 提供本地 fallback 或优雅降级为文本列表 |
| 节点太多（>100）导致性能问题 | 默认只展开当前阶段，其他折叠；或启用 "聚焦模式" |
| LKG 数据没有 edges（旧数据） | 前端兼容：无 edges 时退化为扁平列表布局 |
| 用户拖拽混乱后想恢复 | 提供 "重置布局" 按钮 |
